Turn latency is the whole game. A caller does not experience an agent as accurate
or inaccurate. They experience it as fast or awkward. Past about a second and a
half of silence they assume the line dropped, and they start talking.

So the budget is one to one and a half seconds, end of caller speech to first
audio back. Everything below is about defending it.

## Where the budget goes

Speech to text, a model turn that may call tools, then text to speech, over a
telephony leg. The two easiest to overspend are the ones nobody watches.

**Endpointing** — deciding the caller has finished. Set it eagerly and the agent
talks over people mid-sentence. Set it lazily and every turn inherits the delay.
Per deployment, not a default.

**Tool round-trips** — a tool call inside a turn spends real time. The
[timezone resolver](/systems/scheduling-timezone) is built to about 250ms for
exactly this reason.

Streaming makes the rest survivable. Synthesis starts on the first complete
sentence rather than the finished reply, so the caller hears the beginning of an
answer while the end is still being generated.

## What the agent owns

Conversation flow, turn-taking, interruption handling, and knowing when to stop.
Barge-in has to cancel synthesis rather than queue behind it. Voicemail has to be
recognised — both from platform detection and from the shape of the greeting,
because a recorded greeting is designed to sound like a person answering.

On a follow-up call the agent [reads the lead's history before it
speaks](/systems/conversation-memory) — prior summaries, outcomes, and
where the last conversation ended — so a second call resumes instead of
starting cold. Across live deployments these agents have booked
[over 2,000 appointments](/work/voice-deployments).

Human handoff is a first-class outcome. An agent that cannot hand over is an
agent that will eventually argue with somebody.

## Tradeoffs I took

**Faster model over bigger model.** Reasoning quality is worth little at the far
end of a phone line if it arrives after the caller has started talking. The reply
is one or two spoken sentences.

**Confirm before writing.** Receiving a name and a number is not permission to
book. Details arriving and details being confirmed are separate turns. One extra
round trip, and an entire class of wrong bookings disappears.

**Never speak from context.** Every stated fact is a live read. See
[reliability engineering](/systems/reliability).

## Failure modes it is built against

Voicemail answering like a person. A caller interrupting mid-sentence. Speech
recognition mangling a name or an email — handled by reading back word for word,
but only where a required field would otherwise be stored wrong. Readback on
every field turns a two-minute call into a five-minute one.

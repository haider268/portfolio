You cannot win a distributed race. You can only degrade well.

An agent booking an appointment is a distributed system with a human in the loop
and a two-minute deadline. Telephony, model, calendar, CRM — each can be slow, be
down, or succeed without telling you. The question is never how to stop that. It
is what the caller experiences when it happens.

## The four mechanisms underneath

### Idempotency on writes

Every write that creates something carries a key derived from the content of the
request — the person, the slot, the party — not a random one. Retry the same
booking and you get the same booking back, not a second one.

That is what makes retries safe to have at all. Without it every timeout becomes
a judgement call: did that land?

### Retry on reads, never blindly on writes

Reads are safe to repeat, so a transient failure on an availability check is
retried once before it is believed. Writes are retried only because the key makes
them safe. An unkeyed write retried under uncertainty is how one caller ends up
with three appointments.

### Facts come from tools

The model never answers from its own context. Availability, price, address,
whether a booking exists — read at the moment it is spoken.

The cost is latency: a grounded answer spends a round trip inside a turn the
caller is waiting through, which is why the
[timezone resolver](/systems/scheduling-timezone) is built to a millisecond
budget. What it buys is that being confidently wrong is not a state the system
can reach. Slow is recoverable. Wrong on a phone call is not.

Tools return structured results rather than raising, so a failure is something
the agent can say a sensible sentence about.

### No silent failures

Every workflow error raises a notification. Every provider outage creates a task
against a person. The team finds out from the system, never from the client.

An alert nobody owns is a log line with ambition. A task in someone's queue is a
failure that ends.

## Bounds

A tool loop has a hop ceiling, so a model that keeps calling tools hands over to
a person instead of holding a caller on the line. Sessions have caps. Anything
unbounded is a component that will be found unbounded by a caller.
